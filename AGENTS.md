# AGENTS.md — Where It All Is

**The app:** a calm, offline budget planner sold on Etsy (ADHD-friendly design, not a medical product, not financial advice). Its Today screen answers "how much is safe to spend today?". There's no account and no server: everything lives in the browser's IndexedDB. It ships as one self-contained HTML file plus a hosted PWA. Stack: Vite + Preact + TypeScript, Vitest, Playwright. Product spec: `SPEC.md`. Design audit and tokens: `docs/audit-polish.md`.

**Your branch is visual-only:** styles, layout, copy and icons. Don't change behaviour or data.

## Commands (Node 24)
```
npm install
npx playwright install webkit chromium   # e2e uses installed Chrome (channel 'chrome') + Playwright WebKit
npm run typecheck                         # tsc --noEmit
npm test                                  # unit tests (Vitest)
npm run build:all                         # dist/app.html (full) + dist/demo.html — e2e and audit run on these
npx playwright test                       # e2e, Chromium and WebKit (npm run e2e)
npx playwright test --project=webkit      # one engine only
npm run audit                             # layout audit: iPhone 13 WebKit + Pixel 7 Chromium, light + dark
npx playwright test -c playwright.audit.config.ts screens --project=webkit-iphone13-light --project=webkit-iphone13-dark
                                          # re-capture every screen into docs/screens/
npm run dev                               # dev server (no CSP)
npm run package                           # everything incl. site/, the Start-Here PDFs and dist/Where-It-All-Is.zip
```
Always run `npm run build:all` before e2e or the audit; they test the built files. Before you push: typecheck, unit tests, e2e and the audit must all pass. The audit fails on text under 14 px, tap targets under 44 px, clipping, overlap, low contrast and sideways scrolling.

## Hard rules
- **Money is whole cents** (integer minor units) everywhere. Never floats. Show amounts with the `money` class (tabular numbers).
- **No network calls:** no CDNs, web fonts, analytics or fetches. The build's CSP has `connect-src 'none'`; e2e fails on any request.
- **Single-file build:** `dist/app.html` must keep working when opened straight from disk (`file://`). Inline everything; no runtime asset files.
- **Design tokens only:** spacing, type, radius, shadow and colour come from `src/tokens.css`. `test/tokens.test.ts` fails on any raw px, hex or rgb value in other CSS or in inline styles. Add a token rather than a raw value.
- **Icons:** Lucide only, via `<Icon name=… />` in `src/ui/icons.tsx` (one stroke width, 20 or 24 px). No emoji anywhere in the interface; `test/icons.test.ts` checks. Text the user types can contain anything.
- **Mint `#7CC8B5` is never text on cream:** it's for fills and accents only. Use `--link` / `--text`. A test checks this.
- **WCAG AA contrast** in both light and dark themes. Dark colours are defined in `tokens.css`; change both themes together.
- **44 px touch targets** at minimum (`--tap`). Inputs stay at 16 px or more (iOS zoom).
- **Motion:** subtle only, and off under `prefers-reduced-motion` (the global rule in `styles.css`).
- **Copy:** sentence case, plain words, no shame ("tight", never "failed"). Keep accessible names stable; tests find elements by role and name.

## Do not touch (behaviour, data, money)
- **Calculation:** `src/lib/safeToSpend.ts`, `schedule.ts`, `bills.ts`, `debt.ts`, `envelopes.ts`, `insights.ts`, `money.ts`, `dates.ts`, `transfers.ts`, `quickLog.ts`, `away.ts`
- **Import:** `src/lib/csv/`, `src/lib/rules.ts`, `src/state/importActions.ts`
- **Storage and migrations:** `src/db/` (`schema.ts` migrations, `types.ts`), `src/state/store.ts`, `src/state/actions.ts`, `src/lib/iconKeys.ts`
- **Backup, encryption, sharing:** `src/lib/backup/` (`crypto.ts`, `format.ts`, `merge.ts`, `partner.ts`, `csvExport.ts`), `src/state/backupActions.ts`
If a visual change seems to need any of these, stop and ask instead of editing.

## Tests
- **You may** add new tests, and update tests that check only markup, copy or layout: selectors, accessible names, visible wording, CSS classes, screenshot steps in `audit/`. Mention each change in your PR.
- **You may not** change any test that asserts money values, dates, import results, matching, storage, backup or migration behaviour. That includes all of `test/` except `tokens.test.ts` and `icons.test.ts`, and the amounts, dates, counts and balances inside e2e tests.
- **If one of those fails, stop and report it:** say which test, the expected and actual values, and what you changed just before. Don't adjust the expectation, skip the test or work around it.
